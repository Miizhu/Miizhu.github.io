凤凰曾栖（一）

发表于2026-08-13|更新于2026-08-13|游戏
|总字数:1.7k|阅读时长:5分钟|浏览量:

简读

本篇介绍了Godot游戏开发从配置静态人物图像，人物移动，地图碰撞箱设置，遮挡层设置的方法。

立项

终于开始开发自己的第一款游戏，这次是借助梧桐故里这个校友平台寻找合作伙伴，目标是开发一款以惠州中学生活为背景的游戏
综合考量游戏制作目的，玩家游玩乐趣和我个人的游戏喜好，最终确认开发一款2D像素风探索类游戏，类似于星露谷和宝可梦初几代的画风。

技术栈

游戏引擎：Godot 4.7
编程语言：GDScript
渲染方式: Mobile Renderer

人物搭建

人物主体

这里我们先拿到素材，导入到Godot的项目文件夹里

  1. 新建一个CharacterBody2D的场景，命名为Character
  2. 在这个根节点下建立AnimatedSprite2D 人物动画，CollisionShape2D 人物碰撞箱，Camera2D 人物相机(也就是玩家玩游戏时看到的窗口)
  3. 点击AnimatedSprite2D节点，在应用窗口下方找到动画。选择添加动画，依次配置各个方向的动画。如果你的图跟我一样也是精灵表，只需要在点击添加动画后点击从精灵表中添加帧即可。
  4. 注意，如果添加时显示的横线把人物切断，可以调整分割的格数


    下一步我们来设置碰撞箱：
    点击CollisionShape2D节点，在右侧检查器中找到shape，选择rectangle，将框调整到人物的脚部

人物行走逻辑

搭建好人物主体后，很显然我们需要让他走起来。
现在我们先配置按键输入，让代码能够监控到我们的行动

  1. 点击项目–>项目设置，选择项目设置弹窗上方的输入映射
  2. 在添加新动作处输入名字，点击添加
  3. 点击添加好的动作右侧的加号添加事件

    我们点击节点Character,再在节点树上方找到附加脚本,什么都不用改直接创建就可以。
    接下来把以下代码复制进脚本
# 玩家角色移动脚本
extends CharacterBody2D
# 人物移动速度，可在检查器中调整
@export var speed: float = 150.0
# 获取角色的 AnimatedSprite2D 子节点
@onready var sprite: AnimatedSprite2D = $AnimatedSprite2D
# 记录人物最后面对的方向
# 游戏开始时默认朝右
var facing_direction: String = "right"
# 每个物理帧执行一次
func _physics_process(_delta: float) -> void:
	# 读取四方向输入
	# 同时按两个不冲突的方向键时，
	# Input.get_vector 会自动生成斜向移动：
	# W + A：左上
	# W + D：右上
	# S + A：左下
	# S + D：右下
	var direction := Input.get_vector(
	    "move_left",
	    "move_right",
	    "move_up",
	    "move_down"
	)
	# 根据输入方向计算人物速度
	# 斜向速度会被自动标准化，不会比直线移动更快
	velocity = direction * speed

	# 只有人物正在移动时才更新朝向
	# 停止移动后保留最后一次朝向
	if direction != Vector2.ZERO:
	    facing_direction = get_direction_name(direction)

		# 测试阶段只播放对应方向的单帧 idle 动画
		# 例如：
		# facing_direction = "down_right"
		# 最终播放 idle_down_right
		sprite.play("idle_" + facing_direction)

	# 让 CharacterBody2D 移动并处理碰撞
	move_and_slide()


    # 将移动方向转换成对应的动画方向名称
func get_direction_name(direction: Vector2) -> String:
	# 右
	elif direction.x > 0.0:
	    return "right"

	# 左
	elif direction.x < 0.0:
	    return "left"

	# 下
	elif direction.y > 0.0:
	    return "down"

	 # 上
	else:
	    return "up"

完成后可以运行测试一下。

地图场景搭建

地图素材获取

使用chatgpt进行生图，分为两步:

  1. 将想要的图片需求发给chatgpt，声明自己是小白，让它通过追问，直到确定自己明确需求为止，协助自己写出表达清晰的提示词
  2. 将上述提示词复制，粘贴给另一个聊天框，生图

需要注意的是，如果图片不满意，不要直接在生图窗口指挥怎么修改，因为你的描述不一定足够准确，应重新发回给澄清需求的gpt，精确提示词后再发回给生图ai。

我在这里先确定了人物大小，精灵图高度为64px，人物高度为56px，然后生成地图，以便生成正确的地图大小，否则相对关系很可能会畸变。

地图逻辑实现(碰撞箱，遮挡关系)

将地图放进游戏

  1. 首先创建一个类型为Node2D的节点作为根节点
  2. 然后在根节点下建立一个Sprit2D结点作为背景节点，修改名字为Background(遵守用名规范可以防止忘记这个的作用)
  3. 将素材拖进项目文件夹，再从左下角找到素材，拖进刚才新建的Sprit2D节点的检查器中的texture里，赋予纹路，让背景能显示出来

碰撞箱配置

当这个场景里没有物件需要复现时，可以使用整体配置的简便方法

  1. 在根节点下创建StacticBody2D节点，命名为MapCollision
  2. 在MapCollision节点下，创建一个CollisionShape2D节点，在检查器中选择Shape形式，自己画碰撞框。可选的样式有很多，如RectangleShape2D长方形,CircleShape2D圆形等
  3. 重复此步骤，直到配置完所有碰撞箱

遮挡层

单独扣出需要遮挡层的图片，新建Sprit2D节点，将图片放入texture后移回原位。在检查器调整Background，Character和你需要的遮挡层的图片的order，Z index参数数字越大，图层越高
如果有一个物体是有可能被人物遮挡，也有可能遮挡人物，就需要在地图根场景中的脚本中加入以下代码（这里是Bookcase）

extends Node2D
@onready var character: CharacterBody2D = $Character
@onready var bookcase: Sprite2D = $BookcaseForeground
@export var bookcase_sort_y := 180.0

func _process(_delta: float) -> void:
    # 计算人物脚底坐标
    # character.global_position.y是角色中心点的y坐标
 var character_feet_y := character.global_position.y + 20.0

 if character_feet_y > bookcase_sort_y:
  # 人物位于书架下方，人物遮挡书架
  bookcase.z_index = 0
 else:
  # 人物位于书架上方，书架遮挡人物
  bookcase.z_index = 2

到这里，一个人物能够移动，并拥有合理碰撞箱的场景就完成了。
我也初步完成角色移动逻辑，游戏地图逻辑的跑通。
小开香槟！

结语

其实实际上大部分操作都是GPT指引我完成的。虽然它现在已经可以直接修改文件，编写脚本，但我觉得还是自己学一学会更稳妥，所以我让GPT以教学的形式引导我。这个项目也算是个vibecoding的产物吧！
本篇是博主在完成这些功能后的一个复盘，旨在复习知识与分享流程，欢迎大家指出错漏！
